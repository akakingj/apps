# 계기판 레드라인 0.8.2 — 지도 선점 요청과 첫 화면 전송

## 순정 지도를 켜두고 사용하는 설정

1. 레드라인 **상세설정 → 표시 레이어 → 지도 영역 (기존)**을 선택합니다.
2. BMW **계기판 → 중심 표시 영역 → 지도 보기(Map view)** 또는 꺼짐(Off)을 선택합니다.
3. 앱 자동 켜짐과 스포츠 모드만 표시를 사용하면 스포츠 진입 때 표시를 요청하고,
   스포츠 해제 때 레이어를 반납합니다.

순정 지도와 동일한 map 슬롯에 요청하는 기존 기능을 사용합니다.
renderer의 `map_take_over_stock=1`과 앱의 `contend=true`가 순정 지도 교체를 담당합니다.
전면 중앙(panel)은 별도 표시 영역입니다. 기존 선택은 자동으로 바꾸지 않으므로
지도 교체 방식을 시험하려면 표시 레이어를 직접 **지도 영역**으로 선택해야 합니다.

기본설정의 주황색 문구도 현재 표시 레이어에 따라 달라집니다.
지도 영역이면 지도 보기/꺼짐을 안내하고, 전면 중앙이면 기존 꺼짐 안내를 유지합니다.
Route preview / Assisted Driving View가 레드라인보다 위에 표시되는 문제는 별도입니다.

## 이번 수정

Robertn의 지도 앱은 `MapFeed::show_when_sent()`에서 대기 중 프레임이 소켓으로 전송된
후에 표시를 켭니다. 레드라인도 그 순서를 이미지 클라이언트에 적용했습니다.

기존에는 앞선 소켓 쓰기가 막혔을 때 첫 픽셀 프레임이 대기열에 남아 있는데도
`visible=true`가 먼저 전송될 수 있었습니다. 새 로컬 확장 `showWhenSent()`는 픽셀 메시지를
소켓에 쓴 후에 표시를 켭니다. 이 순서는 소켓의 메시지 순서에 관한 것이며,
실제 계기판 렌더링 완료나 지도 슬롯 선점 성공을 확인한 응답을 뜻하지 않습니다.

- 지도를 선점하는 동안 동일한 레이어 요청을 유지합니다.
- 표시를 한 번 켠 뒤 소켓 drain마다 다시 켜지 않습니다.
- 대기 중 Comfort/꺼짐/오래된 신호/연결 끊김으로 레이어를 삭제하면 늦은 표시 요청도 사라집니다.
- 최초 프레임 쓰기가 backpressure를 반환해도, 이미 소켓에 수락된 프레임 뒤에 표시 명령을 보냅니다.
- 엔진·변속기·MGU 설정 메뉴에 쓰기 API를 추가하지 않습니다.

## 검사와 한계

실제 클라이언트/컨트롤러 코드에 전송이 막히는 소켓을 연결한 테스트로 기존 코드의
픽셀/표시 순서 역전을 재현했고, 수정 후 순서와 취소 동작을 확인했습니다.
45초의 논리적 대기 시간을 모의해 레이어가 재생성되지 않는 것도 확인했습니다.

이것이 사용자 차량의 깜빡임 원인이라고 확정하지는 않았습니다.
cluster-render 자체의 DCSM 선점·재시도 간격은 이번 앱 수정에서 바꾸지 않습니다.
공개 upstream의 실차 기록에도 최초 선점 경쟁이 있으므로 즉시 선점이나 깜빡임 해소를
보장하지 않습니다. 계기판 실제 표시 순서, Assist 가림, 첫 선점 지연은 실차 확인이 필요합니다.

필요하면 [PC 로그 수집 방법](COLLECT-CLUSTER-REDLINE.ko.md)을 사용합니다.
첫 요청부터 표시 성공까지의 렌더러 상태와 앱 상태를 함께 수집하며 차량 설정은 바꾸지 않습니다.

한국어·영어판과 MGU Store에 같은 클라이언트 변경이 적용됩니다.
